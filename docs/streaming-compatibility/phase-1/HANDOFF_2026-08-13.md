## The concepts a fresh agent must not miss

- **The reframe:** the keypoint → *landmark* mapping layer is **retired**. The boundary is
  **keypoint → segment reference geometry**: `SegmentDefinition`s reference keypoints **directly by
  name** (`origin_keypoint` / `long_axis_keypoint` / `twist_keypoint`) to define each rigid-body
  segment's origin / orientation / length. No "canonical keypoints", no "landmarks" — anywhere.
- **A segment is origin + orientation + length.** One declaration, evaluated twice (T-pose reference
  geometry vs. live per-frame pose). `identity == T-pose`, quaternions `wxyz`,
  `q_local = conj(q_parent) · q_child`.
- **VRM 1.0, confirmed against the official spec:** 55 segments = the complete humanoid list (15
  required + all optional-defined: chest/upperChest/neck/shoulders/toes/eyes/jaw/fingers). The face is
  **bones AND blendshapes**: `leftEye`/`rightEye`/`jaw` are driven segments (eyes keypoints exist in
  both mappings; `jaw` is derived in Phase B), and the 52 ARKit channels compose alongside
  (declared-but-null until face tracking; the ARKit→VRM expression mapping lives in the adapter).
  **Plus five FreeMoCap face-detail segments** (nose, ears, mouth corners — added 2026-08-13): the
  model is **60 segments**, `required_keypoints()` = **76**. Mouth corners: MediaPipe tracks them
  (mapped 1:1); RTMPose derives them via `anatomical_offset` (lateral ∓0.3·eye-width).
- **The mapping files are renamed:** `*_to_canonical_mapping.yaml` →
  `*_to_standard_human_mapping.yaml`; detector methods `canonical_mapping_path()` →
  `standard_human_mapping_path()`. freemocap's two path-constant dicts still call the old method name
  **deliberately** — they update in the same pass as the push (Commit Round 1), because they resolve
  against the *installed* skellytracker package.
- **The schematic reference pose:** the T-pose reference is orientations × lengths — no widths/fan
  geometry (ORIGIN branches collapse to the parent's origin; the finger mcps sit at the hand's origin
  except the middle mcp, the hand's distal). Live solves are unaffected (they read live keypoints).
- **Authored-data honesty (§7):** every authored number states its provenance; estimates say so
  (ratio-of-reference-length + stated source). ROM limits are all `None` until Task 5's frame
  conventions are consumed — wait, **they already are** (Task 5 pinned the local-frame convention;
  the addon ROM port is still deferred as `None` — values land when someone ports the addon table).
