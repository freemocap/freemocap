# Client communication and ownership

The running server exposes HTTP controls/resources and a self-describing CBOR
WebSocket. Electron IPC owns local desktop operations and is not a server protocol.
See [API boundary](/docs/architecture/api-boundary) for all supported operations and
[WebSocket contract](/docs/architecture/backend-websocket-server) for both directions.

`TransportService` dispatches validated messages to subscribers without React or
Redux. `MessageDecoder` owns validation/content caches; `FrameResolver` joins channel
rows to each instance's own model definitions. `ServerContextProvider` connects
those subscriptions to application state and views. The default application now imports this implementation from the standalone
`@freemocap/client` package. Version `0.1.0-dev.0` is private and unpublished.

Model/convention/camera subscriptions are change-driven. `ThreeJsCanvas` and
`viewport-frame-transfer.ts` prepare and transfer numerical frames with explicit
buffer return. Preserve those mechanisms while moving client code. Do not replace
self-describing messages with metadata deltas to avoid work already eliminated by
content reconciliation.

Playback fetches recording resources over HTTP and uses the shared presentation
interfaces. Client play/pause/seek is distinct from camera pause, pipeline cancellation,
recording stop and server shutdown. Each has its own server command where applicable.

SDK conformance must cover every supported HTTP operation, every incoming message
kind, outgoing heartbeat/display hints, errors, task lifecycle and asset semantics.
A raw request helper is useful but is not a substitute for typed operation coverage.

## JavaScript and TypeScript client

The local workspace keeps the SDK in sibling `repos/freemocap-client`. The UI's
file dependency consumes its compiled ESM exports; build the SDK before the UI.
The package README owns client usage, its `contracts/coverage.md` maps all 59
supported operations, and `compatibility/0.1.0-dev.0.json` records tested source
fingerprints and evidence. HTTP-only and recording consumers use the `/http` and
`/recording` package subpaths. UI compatibility modules re-export the SDK decoder,
resolver and recording reader so realtime and posthoc rendering share the same
prepared interfaces.

Core's `freemocap.tools.sdk_validation`, `sdk_replay_validation`,
`sdk_live_validation` and `sdk_examples_validation` are integration runners.
They use private outputs, independent reference values and owned server cleanup.
Live execution requires the camera/GPU test slot. Recorded-channel socket replay
checks transport semantics; it does not claim a new inference run or a throughput
benchmark. The live app measurement distinguishes camera capture from processed
frame delivery.
