## The reframe (this session's main outcome)

**The keypoint → landmark mapping is obsolete.** Landmarks named an intermediate layer — fitted points that
a model got fitted to — that pre-dates the reference-geometry / quaternion / kinematics work. The boundary
is now **keypoints → segment reference geometry**: SkellyTracker's keypoints define, as directly as
possible, the rigid-body segments of the standard human.

A segment is **origin + orientation + length**. Length is not adjacent tooling — with origin+orientation the
chain only closes if the length is right, which is why the online/batch length estimators are the third
component of the definition rather than a utility beside it.

**The code already agreed.** Across `skellyforge/kinematics/` and `standard_human/`, "landmark" appears only
in prose and in one field (`HumanBone.proximal_landmark`). The structural vocabulary is `reference_geometry`,
`proximal_joint_center`, `exact_axis`, `approximate_axis`. The docs were the stale half.

**The Blender addon is the reference implementation** — its output is known-good and its constraint model is
a more complete solution than SkellyForge's. Its *vocabulary* (MediaPipe names, `spine.001`, `f_index.01.R`)
is explicitly **not** carried over. Mapping in [SF-SM §1](09-segment-model.md).

## LIVE DEFECT — the realtime orientation solve is broken

Reproduced with a complete, plausible standing pose:

```
ValueError: Bone 'neck' has coincident live proximal and distal joints
            ([0. 0. 1550.] and [0. 0. 1550.]); its direction is undefined.
```

`_BONE_TO_LANDMARK` maps **both** `neck` and `head` to `head_center`. There is **no `try`/`except` in the
aggregator frame loop**, so this propagates and takes the node down. The guard is correct; the bridge table
is feeding it a contradiction. Fixed by SF-SM Task 1 (validation at model load) + Task 9 (delete the table).

Related, same root cause: **only 16 of 21 segments ever produce an orientation.** `_get_distal_position()`
infers the distal from "whichever child is declared first", so `head`, both hands and both toes are silently
skipped, and `hips`/`neck` take their direction from declaration order. The progress log records
"16 world + 16 local quaternions" as a successful verification.

## How to work here

Increment → verify → **update the plans in the same turn**. Write plans to disk before coding; the folder's
rule is "no code until the plan is agreed." Ask when a decision is the user's — anatomy, data-model shape,
scope. Test before fixing: for D1 the failing test decided the convention rather than ratifying a guess.

**Testing discipline ([`14`](../14-engine-testing-strategy.md)):** a test must be able to fail for the
reason it exists. Three ways a parent/child rotation pair goes order-blind — uniform bend, either side at
rest orientation, coaxial rotations. All three are guard tests now.
