# WebSocket contract

This page targets the accepted `sfn26` runtime `90cd474e` (handoff `19acf12c`).
Connect to `/websocket/connect` on the chosen server; do not hard-code a development
port. HTTP remains the command/resource surface and recorded playback transport.

## Independently interpretable messages

Every binary server message is a complete CBOR document with a `kind` and `version`.
Current shape version is 0. Each frame includes convention, cameras, model definitions,
model instances, tracker observations and image bytes. No schema handshake or prior
frame is needed to interpret it. Repeated metadata is intentional.

| Kind | Payload role |
| --- | --- |
| `frame` | Complete frame with ordered model definitions, instance/tracker channels, image and optional diagnostics |
| `log` | Log record |
| `framerate` | Camera-group backend/frontend timing report |
| `app_state` | Server PID and current camera-group/realtime-pipeline state |
| `progress` | `snapshot`: shared task-registry state, including server identity and revision |

Unknown kinds and unsupported versions are skipped by the current decoder. A
malformed known-kind payload at the supported version raises a validation error.
Consumers must surface that distinction rather than silently accept corrupted data.

Envelope `timestamp` and `sequence` exist, but do not imply universal wall-clock or
per-kind freshness guarantees. Frame composition uses the source frame timestamp
and frame number; some other messages retain envelope defaults. Task snapshot
identity/revision supplies task-state ordering. Never substitute reception time for
capture time or silently align unrelated recording clocks.

## Client messages and lifecycle

Clients may send text `ping` and handle `pong`. JSON feedback has `frameNumber`
and optional `displayImageSizes`, keyed by camera with width/height. Follow the
server's finite-number and nonnegative-frame validation. Feedback supplies display
hints and diagnostics; it is not an acknowledgment gate controlling the next frame.

The frame relay favors newest available frames. A slow consumer may miss frames.
Do not claim lossless measurement delivery from a preview connection. Sends share
one serialized writer. Disconnect/reconnect must dispose callbacks and timers,
reset connection-owned caches, and reject late callbacks from retired sockets.
Closing a client does not cancel a pipeline; cancellation is an HTTP command.

## Geometry, identities and memory

Use the declared convention and ordered model/channel definitions. Keypoints,
mapped observations, anatomical landmarks and segment origins are distinct data
products. Names are opaque identities, not a way to infer connectivity. Generic
models and multiple instances must remain supported. Authored geometry is relative
to its named scale reference; measured channels and fitted scale carry their own
units. Do not equate authored proportions with measured positions.

The current decoder owns incoming numerical bytes and retains equal metadata after
content comparison. Changed contents are validated even if IDs or revision counters
stay the same. Numerical byte reuse is safe only under the documented read-only
consumer contract; modifying shared bytes corrupts subsequent consumers. Copy before
mutating. Images have separate transfer ownership and are not shared in the numerical
cache. Worker transfer uses owned frame-sized buffers and returns them only after
presentation releases its values. Wire self-description does not require repeated
renderer reconstruction or transfer of unchanged model definitions.
